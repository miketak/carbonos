# Reference

Reference pages describe the machinery: what exists, what it is called, and
what it does. They do not teach and they do not argue. When a page here and
the code disagree, the code wins and the page needs a pull request.

| Page | Describes |
| --- | --- |
| [Makefile](makefile.md) | Every `make` target, its arguments and what it needs. |
| [CI](ci.md) | The three GitHub Actions workflows, their triggers, jobs and secrets. |
| [Backend modules](backend-modules.md) | The Spring Modulith modules, their public APIs and the events between them. |
| [Frontend structure](frontend-structure.md) | The folders under `frontend/src`, the feature-to-module mapping and the npm scripts. |
| [Environments](environments.md) | Local, staging and production: addresses, services and variables. |
| [Conventions](conventions.md) | Branching, commits, versions, code style and writing style. |
| [Specs](../specs/README.md) | What the product must do, chapter by chapter of the GHG Protocol. |
| [QA procedures](qa/README.md) | Objective-led manual test scripts for staging. |
| [Decision records](../adr/README.md) | Why the tooling and the structure are the way they are. |
