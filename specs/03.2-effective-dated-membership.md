# 03.2: Effective-dated membership

- **Status**: Draft
- **Protocol**: Chapter 3 (boundary) and Chapter 5 (structural changes are
  accounted from the date they occur)
- **Owner**: Michael Takrama
- **Created**: 2026-09-02
- **Modules**: `ghg`, `src/features/ghg`

## Problem

A facility acquired on 1 July belongs to the company's boundary from 1 July.
The Standard accounts its emissions from the transaction date (and triggers
base-year recalculation, spec 06). Today the only tool is a per-inventory
override of the share, and scaling 100% to 50% is not the same number: it
applies half a year's ownership to twelve months of activity, including the
six months the company did not own it. Earlier specs suggested that override;
this spec retires the suggestion.

## Behaviour

- A boundary treatment has **effective from** and **effective to** dates,
  both optional; absent means unbounded within the reporting period.
- An activity record counts for the inventory only when its date falls inside
  its facility's membership window. Outside it, "Review activity data"
  auto-excludes the assignment as `OUTSIDE_BOUNDARY` and the exclusion names
  the window. Re-review reconciles when the window changes, as it does today
  for period and membership changes.
- A boundary version records the windows, so the version states not only
  which facilities but from when to when.
- The BOUNDARY gate warns when a window starts or ends inside the period, so a
  partial-year membership is a visible, deliberate statement.

Given Takoradi terminal acquired 1 July 2025 into a 2025 inventory: the
treatment is effective from 2025-07-01; a January shiploader-diesel record is
auto-excluded as outside the boundary with "member from 2025-07-01"; a
September record is included at the full share; the run cites the version with
the window.

## API

Sketch: `BoundaryTreatmentRequest` gains `effectiveFrom?`, `effectiveTo?`;
`BoundaryEntryResponse` and version entries carry them; exclusion findings and
assignment responses show the window.

## Data

Two nullable date columns on `ghg_boundary_treatments` and
`ghg_boundary_version_entries`.

## Events

None.

## Verification

Integration tests for records before, inside and after a window; re-review
after the window moves; a version carrying the window; the QA scenario's
Takoradi acquisition.

## Non-goals and open questions

Automatic base-year recalculation (spec 06 records the trigger); time-versioned
facility facts (a facility's equity changing on a date is spec 03.1's entity
history, deferred).
