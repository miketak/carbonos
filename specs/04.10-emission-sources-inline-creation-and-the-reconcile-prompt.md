# 04.10: Emission sources, inline creation and the reconcile prompt

- **Status**: Approved
- **Protocol**: Chapter 4 (a source is a physical unit or process that
  releases GHG; scope follows the reporter's relationship to it), Chapter 7
  and ISO 14064-1 section 9.3.3 (completeness rests on a controlled list of
  sources per facility), ISO 14064-3 (a verifier samples the list and how it
  was built), Scope 2 Guidance (purchased energy is an activity whose source
  is someone else's)
- **Owner**: Michael Takrama
- **Created**: 2026-10-04 (Linear ECO-5; audit finding F18 of
  2026-09-11: 23 of 36 imported rows carried no stream)
- **Modules**: `ghg` (`SourceStream`, `GhgService.createActivity` and
  `updateActivity`, `ActivityImportService`, `GhgRules`), `src/features/ghg`
  (the activity form's source field and reconcile notice, the Emission
  sources page), the QA vocabulary, the help

## Problem

Spec 04.3 gave each facility a register of "source streams" so that
completeness has a controlled list to check against and a record's default
scope follows its source. The register lives in a dialog on the Facilities
list, and that is the only place a stream can be created. An analyst arrives
with a diesel invoice, not a list of source definitions: to enter the first
record they leave the activity form, find the facility, open the dialog,
register the stream, and come back. Most do not. The second audit saw 23 of
36 imported rows with no stream, so those rows fell into activity-type rows
of the coverage matrix and no source-level gap could be seen (F18).

There is no hard gate. A record without a stream is saved and shows "Needs
attention" with the readiness issue `NO_STREAM` (spec 04.6). The product
also uses the word "source" for two things: the stream, and the record's
**Data source** field, which says where the figure came from.

## Behavior

### What an emission source is

An emission source is the thing at a facility that activity records are
about: a physical unit or process the company owns or controls that
releases GHG (the Corporate Standard's "source", chapter 4: a generator, a
boiler, a haul truck, which may carry a serial number), or, for indirect
emissions, the purchased energy or contracted activity the company consumes
or pays for, identified by its meter, supplier or contract (purchased grid
electricity, where the meter is the practical handle). A source belongs to
one facility, so coverage has one row per source. Its kind and ownership
(own or contractor-operated) set the default scope and category: own
combustion and process to scope 1, purchased energy to scope 2,
contractor-operated to scope 3 category 1 or 4. The default is confirmed in
each inventory, and the emission factor is chosen there, not on the source,
so the source stays stable while factor editions change. The meter or
supplier field holds the identifier for now; linking a source to a
registered asset is the asset register's job (ECO-6).

### The word

- The user-facing noun is **emission source** ("Emission source",
  "Emission sources", "New emission source…", "No emission source"). Running
  copy may say "source" where the record's **Data source** field is not
  nearby; the readiness copy says "an emission source, a data source and
  evidence". **Data source** keeps its label.
- API names, rule ids, enum values and Java identifiers keep the old word:
  `streamId`, `streamName`, `/api/ghg/facilities/{id}/streams`,
  `NO_STREAM`, `STREAM_ADDED`, `ghg.stream.*`. Only messages change
  ("'Nkran Mine' already has an emission source named 'Standby gensets'.").
- The CSV import column is `emission_source`; a file that still heads the
  column `stream` is read the same way. The template emits
  `emission_source`. Bare `source` is not an alias: an analyst's "source"
  column usually means the invoice.

### A source is created where the data is entered

- The activity form's **Emission source** select lists the facility's
  sources after **No emission source**, then **New emission source…** for a
  role that may write. Choosing it opens a panel under the select: **Source
  name**, **Kind**, **Fuel or material (optional)**, **Meter or supplier
  (optional)** and **Operated by a contractor (its emissions default to
  scope 3)**, with the note "Added to *Facility* when the record is saved."
  Changing the facility, or choosing any other option, clears the panel.
- **Save**, **Save draft** and **Save & next** send the panel as
  `newStream` on the create or update request instead of `streamId`. The
  source and the record are saved in one transaction, the source exactly as
  the register would save it: the same validation, the same role check, the
  same `STREAM_ADDED` history row. A draft saved without a source gets one
  the same way when it is entered.
- A source records how it was born: `origin` is `REGISTER` for one created
  on the Emission sources page and `INLINE` for one created on the activity
  form, with the creating user. The history row of an inline source reads
  "Standby gensets added at Nkran Mine: stationary combustion, during data
  entry". The Emission sources page marks such a source "added during data
  entry". A verifier samples the sources born at the keyboard.
- Naming an existing source (`streamId`) and describing a new one
  (`newStream`) at once is refused under the new source:
  `ghg.activity.stream-and-new-stream`, "Choose an existing emission source
  or describe a new one, not both."
- The readiness issue `NO_STREAM` stays. A record without a source still
  needs attention; the form's hint now reads "This facility has no emission
  sources yet. Choose New emission source… above, or register them under
  Facilities › Emission sources." Nothing is matched silently: a record is
  never attached to a source the user did not choose.

### The reconcile prompt

- Given the facility already has a source whose name equals the typed name
  once case is ignored, the save is refused with
  `ghg.stream.name-duplicate` (409), "'Nkran Mine' already has an emission
  source named 'standby gensets'.", and the problem detail carries
  `candidates`: each matching source's `id`, `name`, `kind`, `defaultScope`
  and `defaultCategory`. The form shows the candidates under a warning with
  a **Use *name*** button beside each; one click attaches the record to that
  source and saves again. No reason gets past an exact match: the name is
  taken.
- Given the typed name is a near miss of an existing source's name, the save
  is refused with `ghg.stream.name-similar` (409), "'Nkran Mine' has an
  emission source with a similar name: 'Standby gensets'. Use it, or give a
  reason to create 'Standby genset' as a separate source.", with the same
  `candidates`. The form offers **Use *name*** per candidate, a field **Why
  is this a different source?** and **Create '*typed*' anyway**, enabled
  once the reason has 10 characters. Re-sending with
  `confirmNewStreamReason` creates the separate source; the reason goes into
  the history row: "Standby genset added at Nkran Mine: stationary
  combustion, during data entry; beside 'Standby gensets': Second 500 kVA
  unit, serial GEN-7781". A shorter reason is refused under the field:
  `ghg.stream.similar-reason-too-short`, "Say in at least 10 characters why
  this is a different source."
- Two names are a near miss when, once lower-cased with punctuation turned
  into spaces, they are equal; or at most one edit apart (two when the
  shorter has 8 characters or more; an edit is an inserted, dropped or
  changed character or two swapped neighbours); or the same words in another
  order; or one is the other plus one word ("Grid supply", "Plant grid
  supply"); or the same words but one, that word two edits apart or sharing
  its first three letters ("Camp generator diesel", "Camp genset diesel");
  or one starts or ends with the other with at most 5 characters left over
  ("Boiler LPG", "Boiler LPG No. 2"). "Kiln 1" beside "Kiln 2" prompts; the
  user answers with a reason. "Boiler LPG" beside "Diesel gensets" does not.
- A refused save burns no record number: the source is resolved before the
  number is taken.
- The Emission sources page checks the exact name only, as the register did;
  the near-miss prompt is the activity form's.

### The Emission sources page

- The **Source streams** dialog of the Facilities list becomes a page per
  facility, `/app/ghg/<org>/facilities/<id>/sources`, under the spec 08
  form-surfaces rule. Breadcrumb **Facilities › *Facility* › Emission
  sources**; the row button on the Facilities list reads **Emission
  sources** and opens to every member, since reading the register is part
  of a verifier's job (spec 01.4); the add form and **Remove** follow the
  role on the page.
- The page lists the facility's sources (name, kind, fuel, meter or
  supplier, "owned or controlled" or "contractor-operated", "defaults to
  *scope*, *category*", and "added during data entry" where it applies) and,
  for a role that may write, carries an **Add emission source** form with the
  same fields as the inline panel. After each add the name, fuel and meter
  clear and the kind and the contractor flag stay, so several sources go in
  one after another. Empty state: "No emission sources registered yet."
- **Remove** opens a confirmation, **Remove emission source?**, with
  **Cancel** and **Remove**. A source with activity records is refused:
  `ghg.stream.has-records`, "'Standby gensets' has activity records. Move
  them to another emission source before deleting it."
- A record that names a source of another facility is refused:
  `ghg.stream.other-facility`, "The emission source 'Standby gensets'
  belongs to 'Obuom Pit', not to 'Nkran Camp'."

## API

- `POST /api/ghg/organizations/{id}/activities` and
  `PUT /api/ghg/activities/{id}` accept, beside the fields of spec 04.6:
  - `newStream`: `{name, kind, fuel?, meterOrSupplier?, contractorOperated,
    note?}`, the shape of `POST /facilities/{id}/streams`; validated the
    same way.
  - `confirmNewStreamReason`: why a near-named source is a separate one
    (10 to 500 characters); ignored when no near miss exists.
- Refusals, all RFC 9457 with a `rule` member:
  - 409 `ghg.stream.name-duplicate` with `candidates`
    (`[{id, name, kind, defaultScope, defaultCategory}]`); also from
    `POST /facilities/{id}/streams` and `PUT /streams/{id}`.
  - 409 `ghg.stream.name-similar` with `candidates`; the activity requests
    only.
  - 422 `ghg.stream.similar-reason-too-short` under
    `errors.confirmNewStreamReason`.
  - 422 `ghg.activity.stream-and-new-stream` under `errors.newStream`.
  - 409 `ghg.stream.has-records` on `DELETE /streams/{id}`.
  - 409 `ghg.stream.other-facility` on a record naming another facility's
    source.
- `SourceStreamResponse` gains `origin` (`REGISTER` or `INLINE`).
- The import template heads the source column `emission_source`; the import
  reads `emission_source`, else `stream`. An unknown name is rejected as
  before: "'Nkran Mine' has no emission source named 'Standby genset 3'".
  The import creates no sources.

## Data

- `V63__source_origin.sql`: `ghg_source_streams.origin varchar(16) NOT NULL
  DEFAULT 'REGISTER'` with a check on `REGISTER` and `INLINE`, and
  `created_by_user_id uuid`. Existing rows came from the register.
- The `UNIQUE (facility_id, name)` constraint of V26 stays the backstop
  behind the case-insensitive check.

## Events

None across module boundaries. The organization's history gets the same
`STREAM_ADDED` row as the register, with the origin and the reason in its
text (spec 01.7).

## Non-goals and open questions

- A default emission factor on a source (ticket T-03). Classification is
  where the analyst drills down to the right factor; a factor on the source
  would drift across years and fight the vintage policy.
- An expected unit on a source, as a hint that makes the import's mixed-unit
  warning deterministic.
- A pre-flight INFO naming the sources created during data entry since the
  last run, and one for two sources at a facility that share kind and fuel.
- A tool that merges two sources into one.
- The near-miss prompt on the Emission sources page.
- Linking a source to an asset: the asset register (ECO-6).
