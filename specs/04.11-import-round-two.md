# 04.11: Import, round two: spreadsheets, sources decided in the preview, and acting on several records at once

- **Status**: Approved
- **Protocol**: Chapter 7 (data collection procedures, documentation of
  data sources, completeness checks), Chapter 9 (a report traceable to its
  records), ISO 14064-1:2018 section 8.2 (GHG information management and
  records), section 9.3.3 (completeness rests on a controlled list of
  sources per facility), ISO 14064-3 (a verifier samples from a line to the
  primary document and asks how a source entered the list)
- **Owner**: Michael Takrama
- **Created**: 2026-10-05 (Linear ECO-24; audit finding F18 of 2026-09-11;
  reviewed by the GHG inventory officer on the same day)
- **Modules**: `ghg` (`ActivityImportService`, `CsvTable` and a new
  `XlsxTable`, `ImportBatch` and a new `ImportDecision`, `GhgService`,
  `EvidenceService`, `GhgRules`), `src/features/ghg` (the import page, the
  register's bulk actions), the QA vocabulary, the help

## Problem

Spec 04.5 gave the product a CSV import that validates the whole file and
imports nothing while one row is wrong; spec 04.6 added the dry run, the
control totals and the kept file; spec 04.10 gave the activity form a way to
create an emission source where the data is entered, with a reconcile prompt
that refuses an exact name and asks for a reason beside a near one. Three
gaps remain between that and what an analyst does on the first day:

- The import still refuses a row whose `emission_source` the facility does
  not have ("'Nkran Mine' has no emission source named 'Standby genset 3'").
  The second audit saw 23 of 36 imported rows carry no source (F18); the
  analyst's choice is to blank the column and lose the source, or to leave
  the import, register the sources one by one, and come back.
- Spreadsheets arrive as XLSX. "Export as CSV first" (04.5) loses the
  original document, which is the artifact a verifier asks for, and the
  export step is where dates turn into locale strings and long numbers into
  exponents.
- The register's only act on several records is **Remove N selected**, and
  it is a loop of single deletions run by the browser: a refusal half-way
  leaves some records removed and some not, under one reason that no history
  row ties together. Giving ten records the same source, tier or invoice
  link means ten corrections.

The file is validated and saved in one request that handles 10,000 rows in
seconds (04.5), so there is no job to track; but a file of a few hundred
rows shows nothing between the click and the result.

## Behavior

### A spreadsheet beside the CSV

- The import accepts `.xlsx` beside `.csv`. The file's kind is read from
  its content (a workbook is a zip), with the extension as a hint; the same
  limits apply (5 MB, 10,000 rows).
- A workbook is read as its first sheet: row 1 is the header, trimmed and
  lower-cased, the same column names as the CSV template (`emission_source`,
  with `stream` still accepted). A date-typed cell is read as `YYYY-MM-DD`;
  a numeric cell as a plain decimal, with no exponent and no trailing `.0`;
  a formula cell as the value the spreadsheet last calculated.
- Warnings, beside those of 04.6: "The workbook has 3 sheets; only 'Sheet1'
  was read." when there is more than one sheet, and "quantity came from a
  formula; the saved value is the cached result" on a row whose quantity,
  period or unit cell is a formula, so a figure that was never recalculated
  is read twice.
- The kept artifact is the file as uploaded, with its SHA-256 (04.6). For a
  workbook, the table as the parser read it is kept beside it as CSV under
  the same batch, and the batch records which parser read the file
  (`csv`, or the workbook reader and its version), so a verifier can
  re-derive the saved figures from the cells without the reader.
- Rejection messages are those of 04.5 and 04.6; row numbers count the
  header as row 1 in both formats.

### An unknown emission source is decided in the preview

- Given a row names a facility the organization has and an
  `emission_source` that facility does not have, the dry run no longer
  rejects the row. The row shows the status **Needs a decision**, counts in
  the control totals under the name as typed, and the preview lists the
  name once under **Decide the unknown emission sources** with the rows it
  covers and, when any exist, the facility's sources whose names are a near
  miss of it (the rule of 04.10: "Standby genset 3" beside "Standby
  gensets"; "Boiler LPG" beside "Diesel gensets" offers nothing).
- For each name the analyst decides one of:
  - **Use *candidate*** (a near miss offered by the preview): the rows
    attach to that source. No reason: the preview proposed it.
  - **Use another source**: any other source of the facility, with **Why
    this source?** of at least 10 characters, since nothing in the name
    suggested it. A shorter reason is refused under the field:
    `ghg.import.map-reason-required`, "Say in at least 10 characters why
    these rows belong to 'Boiler LPG'."
  - **Create it**: the fields of the inline panel of 04.10 (**Source
    name** pre-filled with the typed name, **Kind**, **Fuel or material**,
    **Meter or supplier**, **Operated by a contractor**). Where the name is
    a near miss of an existing source, **Why is this a different source?**
    is required, as on the activity form (`ghg.stream.name-similar`,
    `ghg.stream.similar-reason-too-short`). A name equal to an existing one
    once case is ignored cannot be created: the preview never lists it as
    unknown, because the parser matched it.
- **Add records** stays disabled until every name has a decision. The
  commit sends the file again with the decisions and the SHA-256 the
  preview reported. Nothing is matched silently: a name with no decision is
  rejected as before, and the import, which stays all or nothing, imports
  nothing.
- The decisions are checked against the file, not trusted: a decision for a
  name the file does not contain, two decisions for one name, or a
  `sha256` that is not the uploaded file's is refused as a whole with
  `ghg.import.decision-unused` (409), "The decisions do not match the file.
  Check the file again." A stale preview cannot commit against another file.
- A created source is saved exactly as the register and the activity form
  save it (the same validation, role check and history row), in the same
  transaction as the records, with `origin` `IMPORT` and the creating user.
  Its history row reads "Standby genset 3 added at Nkran Mine: stationary
  combustion, during import of adansi-2025.xlsx (sha256 3f9c2a1b); rows 4,
  9, 17", with the reason appended as in 04.10 when one was given. The
  Emission sources page marks it "added during import". ECO-5's "added
  during data entry" stays for `INLINE`, so a verifier sampling sources born
  at the keyboard can tell one described on purpose from one spawned by a
  spreadsheet cell.
- Each decision is recorded on the batch: the typed name, the facility,
  whether it was mapped or created, the source it resolved to, the rows it
  covered, the reason, who and when. A mapping gets its own history row:
  "'Standby genset 3' in rows 4, 9, 17 of adansi-2025.xlsx mapped to
  'Standby gensets'" (`IMPORT_SOURCE_MAPPED`), with the reason when one was
  given. The record itself holds the source it ended with (04.6: batch and
  row); the typed name survives in the kept file and in the decision.
- The source-documents list shows, per batch, the number of sources added
  during import and the decisions behind the batch.
- The toast after a commit reads "36 records imported." and, when sources
  were created, "36 records imported. 1 emission source added during
  import." (plural "2 emission sources added during import.").

### The import is a page

- The import leaves its modal for a page, `/app/ghg/<org>/activity/import`,
  breadcrumb **Activity data › Import**, under the spec 08 form-surfaces
  rule (amended: a batch operation whose preview is a document of its own
  is a page). The form carries the accessible name **Import activity data**,
  so a tester or a driver addresses it the way it addressed the dialog.
- The page keeps the two steps: **Use the activity template** (**Download
  CSV template**, **What each column must contain**) and **Select your
  completed spreadsheet**, whose file field is labelled **Spreadsheet file**
  and reads "Choose a CSV or XLSX file" and "Or drop it here. Up to 5 MB;
  the file is kept with the records it creates." Then, once the dry run
  returns: the rejections banner of 04.6, **Decide the unknown emission
  sources** when there are any, **Control totals**, the warnings, and
  **N records to add**.
- **Import CSV** on the Activity data toolbar becomes **Import**, a
  role-gated button (spec 01.4) that navigates to the page; a Verifier sees
  it disabled with the tooltip. **Add records** returns to the Activity data
  page with the toast; **Cancel** returns without importing.
- While a request runs, the page reports its stage under the file field:
  "Uploading… 42%" from the browser's upload progress, then "Checking 480
  rows…" (the row count is the file's line count; a workbook reads
  "Checking the workbook…"), then on commit "Adding 480 records…". The
  controls are disabled meanwhile. The request is the same single request
  as before; nothing is queued.

### Acting on several records at once

- The register's footer, with rows selected, offers **Assign emission
  source**, **Set data quality tier**, **Add evidence link** and **Remove N
  selected** to a role that may write. Each opens a modal (a batch
  operation): the one field it needs, **Reason** (at least 5 characters, as
  a single correction), and the count, "Applies to 12 records."
- One request carries the whole act and it is all or nothing: the backend
  applies every record in one transaction or refuses the act with
  `ghg.activity.bulk-refused` (409), "Nothing was changed: 2 of 12 records
  refuse the action.", listing each refused record with its reference, the
  rule and its message, so the analyst deselects it and tries again. A
  partial result with no record of what did not apply is worse for the
  trail than a refusal that names the records.
- Each record is changed exactly as a single edit changes it: a correction
  with its per-field revision (04.4), a removal with its tombstone and
  reason (04.4), an evidence link with its evidence row (04.6). The
  revisions and tombstones of one act share a `bulk_id`, and the
  organization's history gets one row for the act: "Emission source
  'Standby gensets' assigned to 12 records: March invoices name the standby
  unit" (`RECORDS_BULK_CORRECTED`, with the action, the count and the
  reason), so 12 revisions read as one act by one person.
- **Assign emission source** fills, it does not move: it is offered when
  every selected record is at one facility and has no emission source, and
  lists that facility's sources. Otherwise the button is disabled with
  "Select records at one facility with no emission source." The backend
  refuses a record that already has a source (`ghg.activity.has-source`,
  "ACT-0007 already has an emission source; change it on the record.") and
  one at another facility (`ghg.stream.other-facility`). Changing a
  record's source changes its default scope and category (04.10), so that
  stays a correction of one record, with its own reason.
- **Set data quality tier** takes a tier of 1 to 5. The modal warns, without
  refusing, when the selection spans more than one source kind: "The
  selected records are of 2 kinds of emission source; a tier is assessed
  per source and method." A record already at that tier is left as it is
  and not counted as changed.
- **Add evidence link** takes **Name** (optional) and **URL** (http or
  https, `ghg.evidence.link-scheme`) and attaches the same link to each
  record: one invoice, many lines.
- **Remove N selected** keeps its dialog, **Remove N records?**, and moves
  to the same request. A record a run has read is refused by name with the
  rule the single removal now carries, `ghg.activity.used-in-run`,
  "ACT-0007 is used in run R-3 and cannot be removed."; one already removed
  with `ghg.activity.already-removed`.
- An act over no records, or over more than 500, is refused:
  `ghg.activity.bulk-empty`, `ghg.activity.bulk-too-many` ("Select at most
  500 records at once.").
- A correction through the bulk request obeys exactly what a single
  correction obeys today: a removed record cannot be corrected, a fact
  cannot go back to a draft, the reason is required. The single correction
  has no frozen-inventory or run-usage check (runs snapshot their inputs,
  spec 05.1), and this spec does not add one; spec 04.9 decides where a
  correction's reason becomes a reclassification.

## API

- `POST /organizations/{id}/activities/import?dryRun=true|false` (multipart):
  - `file`: `.csv` or `.xlsx`.
  - `decisions` (optional, `application/json`): `{sha256, items: [{facilityId,
    name, mapTo: streamId, reason?} | {facilityId, name, create: {name, kind,
    fuel?, meterOrSupplier?, contractorOperated, note?}, reason?}]}`.
  - The response of 04.6 gains `sha256`, `unknownSources: [{facilityId,
    facility, name, rows: [int], candidates: [{id, name, kind, defaultScope,
    defaultCategory}]}]`, `sourcesCreated` and, on a preview row, the status
    `NEEDS_DECISION`.
  - Refusals (RFC 9457, with `rule`): 422 `ghg.import.map-reason-required`
    under `errors.decisions[i].reason`; 409 `ghg.stream.name-similar` and
    422 `ghg.stream.similar-reason-too-short` as in 04.10; 409
    `ghg.stream.other-facility`; 409 `ghg.import.decision-unused`.
- `GET /organizations/{id}/activities/import-batches` rows gain
  `sourcesCreated`, `parser`, `renderedAvailable` and `decisions:
  [{name, facility, kind: MAPPED | CREATED, streamName, rows, reason,
  decidedBy, decidedAt}]`. `GET /import-batches/{id}/rendered.csv` returns
  the table as read, for a workbook.
- `POST /organizations/{id}/activities/bulk`: `{ids: [uuid], reason, action:
  REMOVE | ASSIGN_SOURCE | SET_TIER | ADD_EVIDENCE_LINK, streamId?,
  dataQualityTier?, link?: {name?, url}}` → `{applied, records: [ref],
  bulkId}`. Refusals: 409 `ghg.activity.bulk-refused` with `refused:
  [{id, recordRef, rule, message}]`; 422 `ghg.activity.bulk-empty`,
  `ghg.activity.bulk-too-many`, `ghg.reason.too-short`; 422 under the
  action's field when it is missing.
- `DELETE /activities/{id}` names its refusals: `ghg.activity.used-in-run`
  (409) replaces the message-only refusal; `ghg.activity.already-removed`
  stays.
- `SourceStreamResponse.origin` gains `IMPORT`.

## Data

`V64__import_decisions_and_bulk.sql`:

- `ghg_source_streams.origin` check widened to `REGISTER`, `INLINE`, `IMPORT`.
- `ghg_import_batches`: `parser varchar(60) NOT NULL DEFAULT 'csv'`,
  `rendered_storage_key varchar(200)`, `sources_created integer NOT NULL
  DEFAULT 0`.
- `ghg_import_decisions`: `id`, `batch_id` (FK), `facility_id` (FK),
  `typed_name varchar(120)`, `kind varchar(8)` (`MAPPED`, `CREATED`),
  `stream_id` (FK), `rows integer[]`, `reason varchar(500)`,
  `decided_by_user_id uuid`, `decided_by varchar(320)`, `decided_at
  timestamptz`; index on `batch_id`.
- `ghg_activity_revisions.bulk_id uuid` and `ghg_activities.delete_bulk_id
  uuid`, both nullable; index on each.
- `ghg_audit_events` gains the actions `IMPORT_SOURCE_MAPPED` and
  `RECORDS_BULK_CORRECTED` (the enum is a string column; no constraint to
  widen).

## Non-goals and open questions

- Importing classifications: an inventory decision, not a fact (04.5).
- Monthly meter-read templates: ECO-27, with the documented zero, since an
  idle source's template row must otherwise be deleted.
- Which facility-months a file covers, and outliers against a source's
  history (04.6): ECO-25.
- A queued import with a progress bar from the server; the request is
  synchronous and the stages are the browser's.
- Moving records to another emission source in bulk: a reclassification per
  record (04.10, 04.9).
- An expected unit on a source (04.10): ECO-26.
- `.xls` and `.ods`: save as `.xlsx` or `.csv`.
