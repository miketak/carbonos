# 04.5: Bulk import and the activity register

- **Status**: Implemented
- **Protocol**: Chapter 7 (data collection procedures, completeness checks),
  ISO 14064-1 section 9.3.3 (a controlled list of sources with data for
  every period)
- **Owner**: Michael Takrama
- **Created**: 2026-09-09 (audit finding F15 and the volume note, ticket
  T-18); implemented 2026-09-09
- **Modules**: `ghg` (`ActivityImportService`, `CsvTable`, the register
  search, the paged activity view, the coverage matrix), `src/features/ghg`
  (activity page toolbar and import dialog, activity view filters, coverage
  matrix)

## Problem

The only way to enter a record was one modal at a time, and thirty records
already displayed as an unsorted list. A mine site produces thousands of
dispensing lines a year and practitioners work from spreadsheets. The
coverage matrix keyed on free-text activity type, so a stream with no data
at all was invisible rather than shown as empty.

## Behavior

- **CSV import.** The activity page offers a template
  (`activity-import-template.csv`: the header and one example row) and an
  **Import CSV** dialog. Columns: `facility`, `stream`, `activity_type`,
  `quantity`, `unit`, `period_start`, `period_end`, `data_source`,
  `evidence_ref`, `data_quality`, `data_quality_tier`,
  `uncertainty_percent`, `note`; only the first five and `period_start` are
  required, `period_end` defaults to the start, `data_quality` to
  `MEASURED`. The whole file is validated first and **nothing is imported
  while any row is rejected**, so a corrected file can be uploaded again
  without doubling records. The result names each rejected row and what was
  wrong (an unknown facility or stream, a quantity that is not a number, a
  date that is not `2025-03-31`, a future date, a period ending before it
  starts, a bad quality label or tier). A row that repeats a record already
  on file, or an earlier row of the same file (same facility, activity,
  quantity, unit and period), is rejected as a duplicate. Files up to 5 MB
  and 10,000 rows; UTF-8, a BOM tolerated, quoted fields and CRLF as RFC
  4180 describes.
- **The register.** The activity page is a paged register: a search box
  (activity, facility, stream, unit, source, evidence reference, note),
  filters by facility, stream and period, sort by period, facility,
  activity, quantity or entry time, and pages of 50. The list stays
  responsive at thousands of records because the server pages and filters.
- **The activity view.** The inventory's activity view pages the same way,
  with a search box, a facility filter and a status filter (included,
  excluded, unclassified), and shows the counts by status, so "12 of 3,400
  still unclassified" is one glance.
- **Coverage per stream.** The coverage matrix has one row per stream of
  each facility in the boundary, even a stream with no records (every
  month empty), and one row per activity type for records that name no
  stream. A missing month or a silent stream is visible before the run.
- **Volume.** Run lines and imports insert in JDBC batches of 50.

Given a spreadsheet of 2025 dispensing with one row whose quantity reads
"12,5OO": the import reports row 14, "quantity '12,5OO' is not a number",
and imports nothing; corrected, it imports every row, and uploading it
again rejects every row as a duplicate. Given 3,400 records: the register
opens on the first 50, newest period first, and a search for "LPG" narrows
it in one request.

## API

- `GET /organizations/{id}/activities/page?q&facilityId&streamId&from&to&sort&dir&page&size`
  → `{items: ActivityResponse[], page, size, total}`; `sort` is one of
  `periodEnd` (default), `periodStart`, `facility`, `activityType`,
  `quantity`, `createdAt`; `size` up to 500. `GET /organizations/{id}/activities`
  keeps returning the whole list.
- `POST /organizations/{id}/activities/import` (multipart `file`) →
  `{imported, rejected: [{row, message}]}`; 422 `errors.file` for an empty
  file, one over 5 MB or 10,000 rows, or a header without the required
  columns. `GET /organizations/{id}/activities/import-template.csv`.
- `GET /inventories/{id}/assignments/page?q&facilityId&status&page&size` →
  `{items: AssignmentResponse[], page, size, total, included, excluded,
  unclassified}`. `GET /inventories/{id}/assignments` keeps returning the
  whole list.
- `CoverageRow` gains `streamId` and `streamName`; `activityType` is null
  for a stream row.

## Data

None. `application.yaml` sets Hibernate's JDBC batch size to 50 with
ordered inserts and updates.

## Events

None.

## Verification

(the template; a file with two bad rows imports nothing and names them; a

## Later changes

Spec 04.6 (2026-09-11) adds a dry run to the import (each row with its
readiness, control totals and warnings before anything is saved), keeps the
imported file with its digest and stamps each record with its row, and gives
the register its readiness tabs, counts and month filter.

## Non-goals and open questions

- XLSX import; export the sheet as CSV first. The template opens in a
  spreadsheet and saves back as CSV.
- Importing classifications; records are classified in the inventory.
- A running import that reports progress; the file is validated and saved
  in one request, which handles 10,000 rows in seconds.
